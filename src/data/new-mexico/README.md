# New Mexico Permian Flaring Pipeline

This directory contains the data extraction and preprocessing scripts for the `summer26-permian-flaring` project. The pipeline is designed to handle massive raw datasets from the New Mexico Oil Conservation Division (OCD), extracting, cleaning, and linking historical production, waste, and facility data.

Several of these scripts process large XML databases using `lxml.etree.iterparse` to maintain a flat memory profile and prevent RAM exhaustion during execution.

---

## ⚙️ Usage & Execution Instructions

While all files can be executed using the standard python command (e.g., `python parse_well_registry.py`), there are critical environment requirements you must meet before running them:

* **Hardcoded Environment Paths:** Every script relies on a hardcoded project root directory. You **must** ensure your system has the following directory structure set up relative to your home directory, or the scripts will fail to find the raw inputs:
    `~/work/projects/summer26-permian-flaring/data/raw/new-mexico/`
    *(If your project is located elsewhere, you must manually update the `project_root` variable at the top of every script).*
* **Dependencies:** These scripts require external libraries that are not part of the Python standard library. Ensure you have installed `pandas` and `lxml` before execution.
* **Execution Order:** Run `parse_pod_mapping.py` **before** `parse_legacy_flaring.py`. The legacy flaring script requires the POD-to-API mapping CSV generated by the mapping script to execute its broadcast join.

## 📂 Data Parsing Scripts

### `parse_well_registry.py`
* **Purpose:** Cleans and filters the New Mexico OCD well registry for downstream spatial analysis. Drops heavy text/geometry columns and forces string data types on identifier columns (like API and OGRID) to prevent the loss of leading zeros. Filters exclusively for Permian Basin counties (Lea and Eddy).
* **Input:** `New_Mexico_OCD_Oil_and_Gas_Wells.csv`
* **Complete Output Location:** `~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_wells_spatial.csv`

### `parse_waste_beneficial_upstream.py`
* **Purpose:** Extracts upstream natural gas waste and beneficial use records. Streams the XML database and implements a "fail-fast" optimization that immediately drops any records where the volume is zero, significantly reducing the size of the output dataset.
* **Input:** `upstreamnaturalgaswastebeneficialuse.xml`
* **Complete Output Location:** `~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_upstream_beneficial_use_nonzero.csv`

### `parse_podvolume.py`
* **Purpose:** Extracts historical gas sales and delivery volumes. Streams the massive 20GB POD volume database to extract 'Delivery/Sales' (Disposition Code 'D') volumes for Gas ('G'). Aggregates volumes directly by Operator ID (OGRID) rather than well-level.
* **Input:** `podvolume.xml`
* **Complete Output Location:** `~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_gas_sold.csv`

### `parse_pod_mapping.py`
* **Purpose:** Establishes the relationship between Point of Delivery (POD) IDs and individual well API numbers. Reconstructs standard 10-digit API numbers and uses a memory-efficient set to output only unique POD-to-API pairs, eliminating decades of duplicate records.
* **Input:** `podwc.xml`
* **Complete Output Location:** `~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_pod_to_api_mapping.csv`

### `parse_legacy_flaring.py`
* **Purpose:** Generates the historical flaring dataset required for the Difference-in-Differences (DiD) panel analysis. Loads the unique POD-to-API mapping into memory and streams the 20GB volume XML, filtering strictly for Flaring ('F') and Venting ('V') events within the 2015–2020 pre-treatment window.
* **Inputs:** `podvolume.xml` (Volumes) & `nm_pod_to_api_mapping.csv` (Crosswalk)
* **Complete Output Location:** `~/work/projects/summer26-permian-flaring/data/interim/nm_legacy_flaring_2015_2020.csv` *(Note: This outputs directly to the `interim` directory, bypassing the `new-mexico` subfolder).*

### `parse_facilities.py`
* **Purpose:** Extracts location, status, and operator metadata for New Mexico oil and gas facilities. Streams the facility XML and flattens the required node structure (coordinates, facility types, and operator details) into a structured CSV format.
* **Input:** `facility.xml`
* **Complete Output Location:** `~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_facilities.csv`

### `parse_waste_xml.py`
This script processes the massive `upstreamnaturalgaswaste.xml` dataset provided by the New Mexico OCD. It streams the XML data directly from disk to prevent memory overflow, extracting key reporting fields while optimizing output size.

**Key Features:**
* **Zero-Volume Filtering:** Implements a "fail-fast" optimization that immediately drops any rows where the reported waste volume is zero, drastically reducing the final CSV size.
* **Streaming ETL:** Utilizes `lxml.iterparse` in binary mode to handle UTF-16 decoding on the fly while aggressively clearing processed nodes from memory.
* **Targeted Output:** Extracts essential columns (`Year`, `Month`, `OGRID`, `Structure_Type`, `Structure_ID`, `Waste_Type`, `Reporting_Category`, `Volume_MCF`, `Method`) into an interim CSV ready for analysis.

**Usage:**
```bash
python parse_waste_xml.py
# Outputs to: ~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_upstream_waste_nonzero.csv
```

### `parse_production.py`
This script handles the extraction and formatting of the `wcproduction.xml` dataset. Because the raw production file contains state-wide data for all product types, this script applies strict geographic and product-level filtering during the stream to isolate the data relevant to the project.

**Key Features:**
* **Geographic Filtering:** Only processes records for Lea (025) and Eddy (015) counties.
* **Product Filtering:** Drops non-hydrocarbon records, keeping only Oil ('O') and Gas ('G') production data.
* **API Reconstruction:** Automatically stitches the isolated `api_st_cde`, `api_cnty_cde`, and `api_well_idn` fields together, padding them with zeros to generate a standard 10-digit `API_Number`.

**Usage:**
```bash
python parse_production.py
# Outputs to: ~/work/projects/summer26-permian-flaring/data/interim/new-mexico/nm_wcproduction_filtered.csv
```

## 🛠️ Utilities

### `column_extraction.py`
This script is designed to rapidly extract column names and their associated data types from massive XML data dumps. Rather than parsing the entire dataset, it uses stream-based parsing to isolate and read only the embedded `xsd:schema` definition at the beginning of the file, allowing it to process large files in milliseconds with virtually zero memory overhead.

**Key Features:**
* **Memory Efficient:** Never loads the full file into RAM; stops executing immediately after the schema block is parsed.
* **Auto-Detection:** Automatically detects between UTF-16 (common in SQL Server exports) and UTF-8 encodings.
* **CSV Export:** Optionally exports the extracted schema directly to a clean CSV file for easy mapping.

**Usage:**
```bash
# Print columns and data types to the terminal
python column_extraction.py your_large_file.xml

# Export the schema to a CSV file
python column_extraction.py your_large_file.xml -o output_schema.csv
```

### `print_xml_rows.py`
This script provides a quick, human-readable preview of the actual data inside a massive XML file. It streams the data records just long enough to capture a user-defined number of rows, then outputs them to the terminal in a neatly formatted ASCII table. Crucially, it reads the file's schema first to ensure the columns are displayed in their exact original order.

**Key Features:**
* **Safe for Big Data:** Utilizes highly optimized `lxml.iterparse` event streaming and aggressive garbage collection to prevent memory bloat.
* **Preserved Ordering:** Actively maps data back to the structural layout defined in the `xsd:sequence` schema block.
* **Customizable:** Allows you to define exactly how many sample rows you want to preview.

**Usage:**
```bash
# Preview the first 5 rows (default)
python print_xml_rows.py your_large_file.xml

# Preview a custom number of rows (e.g., 50 rows)
python print_xml_rows.py your_large_file.xml -n 50
```
